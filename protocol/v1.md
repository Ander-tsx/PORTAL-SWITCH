# PortalSwitch wire protocol — version 1

Status: **draft**. Message layer stable for review; transport mapping provisional until the
channel-strategy measurements on real networks (wired and Wi-Fi) are done.

Test vectors: [`vectors/v1.json`](vectors/v1.json) (generated by
[`tools/gen_vectors.py`](tools/gen_vectors.py), an encoder independent from the Rust codec).

## 1. Goals

- Input never waits behind clipboard or file data.
- Every connection is encrypted and mutually authenticated. No plaintext mode.
- Small, fixed-layout messages on the input path; bounded sizes everywhere.
- Forward compatible: newer peers can add messages and fields without breaking older ones.
- **Transport-independent message layer**: the same frames run over two TCP+TLS connections or
  over QUIC streams. Swapping the transport must not change any message.

## 2. Topology and roles

- Star topology per session: the **host** (machine with the physical keyboard and mouse) holds one
  link to each peer. Peers never talk to each other.
- Any machine can accept or initiate a link; "acceptor"/"initiator" is a transport detail. The
  host role is declared in `Hello` (flag `HOST`). Exactly one side of a link sets it.
- Input messages flow host → peer only. A peer sending an input message is a protocol violation.

## 3. Link abstraction

A **link** between two machines provides two logical channels, both reliable, ordered and
encrypted:

| Channel | Carries | Requirements |
|---|---|---|
| **control** | session, topology, input, clipboard announcements, drag announcements | lowest latency; never blocked by bulk; small frames |
| **bulk** | clipboard payloads, file transfers | high throughput; flow-controlled independently of control |

The message layer only needs `send(channel, frame)` / `recv(channel) -> frame` plus
"link closed". Transport mappings (§10) implement this.

## 4. Framing

All integers are **little-endian**. A frame is:

| Field | Type | Notes |
|---|---|---|
| `length` | u32 | bytes that follow this field (`type` + payload). `2 ≤ length ≤ max` for the channel |
| `type` | u16 | message type (§6). Bit 15 = **critical** |
| payload | `length − 2` bytes | message layout (§7) |

Receivers validate `length` **before** allocating. Maximum `length`: control **65 536**, bulk
**262 208** (256 KiB of data + headers). Exceeding it → `Goodbye(FRAME_TOO_LARGE)` and close.

### Forward compatibility

- **Unknown type, critical bit clear** → ignore the frame.
- **Unknown type, critical bit set** → `Goodbye(PROTOCOL_VIOLATION)`.
- **Known type, payload longer than the known layout** → parse the known prefix, ignore the
  rest. New fields are only ever **appended**.
- **Known type, payload shorter than its minimum** → `Goodbye(PROTOCOL_VIOLATION)`.
- Negotiated **capabilities** (§8.2) gate optional features; never send a feature-specific
  message the peer did not advertise.

### Primitive encodings

| Name | Encoding |
|---|---|
| `u8/u16/u32/u64`, `i16/i32` | fixed-width LE |
| `bool` | u8, 0 or 1; anything else is a violation |
| `bytes16`, `bytes32` | fixed 16 / 32 raw bytes |
| `str` | u16 byte length + UTF-8 bytes (must be valid UTF-8; per-field max in §7) |
| `blob` | u32 byte length + raw bytes |
| `list<T>` | u16 count + `count` × T |

## 5. Session lifecycle

```
initiator                                   acceptor
   | ── transport connect + TLS 1.3 (mutual) ── |
   | ── Hello ─────────────►  ◄──────── Hello ── |   both send immediately, symmetric
   |           (validate version, roles, pairing state)
   |                          ◄── SessionStart ── |   acceptor; carries bulk_token
   | ── bulk channel open (+ BulkAttach) ───────► |   (dual-TCP mapping only)
   | ◄────── ScreenInfo ─── (peer)  ScreenInfoAck ─ | peer is "ready" after first valid ScreenInfo
   |          … Ping/Pong, Enter/Leave, input, clipboard, transfers …
   | ── Goodbye ──────────────────────────────►  |   either side, then close
```

- **Handshake timeout**: `Hello` must arrive within **5 s** of the TLS handshake completing;
  `Hello` payload ≤ **4 KiB**.
- **Version check**: majors must be equal; effective minor = `min(local, remote)`. Mismatch →
  `Goodbye(INCOMPATIBLE_VERSION)` with the local version in `detail`.
- **Roles**: both or neither `HOST` → `Goodbye(PROTOCOL_VIOLATION)`.
- **Duplicate machine**: a second link from an already connected `machine_id` →
  `Goodbye(DUPLICATE_MACHINE)` on the new link.
- **Unknown machine**: if the peer's certificate is not pinned, run pairing (§9) instead of
  closing.
- **Ready**: the peer is added to the layout as connected only after a valid `ScreenInfo`
  (at least one monitor, all sizes > 0). A cursor outside all monitors is replaced by the centre
  of the first monitor.

### Liveness

- Each side sends `Ping` every **1 s** (configurable) on control; the other answers `Pong`.
- **Any** received frame on either channel counts as liveness.
- No traffic for **3 intervals** → link is dead: close, release held input, return the cursor to
  the host if it was on that peer.
- `Pong` echoes the sender's timestamp → RTT for diagnostics. No clock synchronisation needed.

### Shutdown

`Goodbye(reason, detail)`, then close the transport. A side that sent `Goodbye` waits at most
**1 s** for the transport to close before dropping it.

## 7. Message layouts

Field order is the wire order. "min" = minimum payload length.

### Session

**Hello** `0x8001` (min 32)
| Field | Type | Notes |
|---|---|---|
| `major` | u8 | 1 |
| `minor` | u8 | 0 |
| `flags` | u16 | bit 0 `HOST` |
| `capabilities` | u64 | §8.2 |
| `machine_id` | bytes16 | stable random ID (UUIDv4 bytes) |
| `machine_name` | str ≤ 64 | user-facing name |
| `app_version` | str ≤ 32 | e.g. `0.1.0` |

**SessionStart** `0x8002` (min 32): `session_id: bytes16`, `bulk_token: bytes16` (random, single use).

**Goodbye** `0x8003` (min 2): `reason: u16`, `detail: str ≤ 256` (optional; absent = empty).

| reason | Name |
|---|---|
| 1 | NORMAL |
| 2 | INCOMPATIBLE_VERSION |
| 3 | DUPLICATE_MACHINE |
| 4 | NOT_PAIRED |
| 5 | PAIRING_REJECTED |
| 6 | PROTOCOL_VIOLATION |
| 7 | FRAME_TOO_LARGE |
| 8 | TIMEOUT |
| 9 | SHUTTING_DOWN |
| 10 | LIMIT_EXCEEDED |
| 11 | INTERNAL_ERROR |

**Ping** `0x0004` (min 12): `nonce: u32`, `sender_time_us: u64` (sender's monotonic clock).
**Pong** `0x0005` (min 12): `nonce: u32`, `echoed_time_us: u64`.
**BulkAttach** `0x8006` (min 16): `bulk_token: bytes16`. First and only control-type frame on a
bulk connection; wrong token → close.

**PairStart** `0x8010` (min 0): asks the other side to show the pairing code (§9).
**PairConfirm** `0x8011` (min 1): `accepted: bool`.

### Input (host → peer)

Common prefix for all input messages: `enter_seq: u32` (must equal the current `Enter`, else the
peer discards the message) and `t_us: u32` (host monotonic time in µs, wrapping; diagnostics only).

**Enter** `0x8101` (min 17): `enter_seq: u32`, `x: i32`, `y: i32` (peer's global coordinates),
`toggles: u8` (bit 0 Caps Lock, 1 Num Lock, 2 Scroll Lock), `modifiers: u32` (§8.1).
`enter_seq` is strictly increasing per link.

**Leave** `0x8102` (min 4): `enter_seq: u32`. Peer releases everything it holds, then answers.
**LeaveAck** `0x8103` (min 5): `enter_seq: u32`, `ok: bool`. Not `ok` → host aborts the switch.
The host does not wait for `LeaveAck` longer than **250 ms**; on timeout the switch proceeds and
the peer is sent `ReleaseAll`.

**MouseMotion** `0x8104` (min 12): prefix, `dx: i16`, `dy: i16`. Relative motion in the peer's
pixels after speed normalisation; sub-pixel remainders are kept on the host. Consecutive motion
may be coalesced by the sender (sum of deltas) when the channel is congested.

**MouseAbsolute** `0x8105` (min 16): prefix, `x: i32`, `y: i32`.

**MouseButton** `0x8106` (min 10): prefix, `button: u8` (1 left, 2 right, 3 middle, 4 back,
5 forward, 6–32 extra), `down: bool`. The peer derives click counts itself.

**Wheel** `0x8107` (min 13): prefix, `dx: i16`, `dy: i16` in **1/120 notch** units (positive =
right / away from user), `flags: u8` (bit 0 `CONTINUOUS`: high-resolution device such as a
trackpad). The receiver applies its own natural-scrolling preference.

**Key** `0x8108` (min 30)
| Field | Type | Notes |
|---|---|---|
| prefix | u32 + u32 | `enter_seq`, `t_us` |
| `action` | u8 | 0 up, 1 down, 2 repeat |
| `repeat_count` | u16 | ≥ 1 for repeat, else 0 |
| `key_id` | u32 | host's identifier for the physical key; pairs down/up |
| `hid_usage` | u32 | `(usage_page << 16) \| usage`: page 0x07 keyboard, 0x0C consumer (media), 0 unknown |
| `codepoint` | u32 | Unicode scalar the host layout produced, or 0 |
| `named_key` | u16 | logical non-character key (§8.3), or 0 |
| `modifiers` | u32 | §8.1, state at the time of the event |
| `flags` | u8 | bit 0 `DEAD_KEY`, bit 1 `KEYPAD` |

Rules (spec 03): up for an unknown `key_id` is ignored; repeat for an unknown `key_id` is
ignored; down for a `key_id` already down is treated as repeat.

**ReleaseAll** `0x8109` (min 4): `enter_seq: u32`. Peer releases every synthetic key/button.

### Clipboard announcements

**ClipboardGrab** `0x0201` (min 12): `clip_seq: u32`, `enter_seq: u32` (latest seen),
`formats: u32` (bit 0 text, 1 HTML, 2 PNG, 3 RTF). Data never travels on control; it moves as a
transfer of kind `CLIPBOARD` (§7 transfers) following the lazy rules of spec 04.

### Transfers (bulk)

Transfers carry clipboard contents and files. Several transfers may interleave at chunk
granularity. Chunks are ≤ **256 KiB** of data so cancellation and interleaving stay responsive.

**DragStart** `0x0301` (control, min 18): `transfer_id: u32`, `item_count: u32`,
`total_size: u64`, `first_name: str ≤ 255`. Announces a drag in progress so the destination can
start its native drag session before data arrives.

**TransferBegin** `0x8302` (min 21): `transfer_id: u32` (unique per sender per link),
`kind: u8` (1 clipboard, 2 files), `item_count: u32`, `total_size: u64`, `ref_seq: u32`
(`clip_seq` for clipboard, else 0).

**TransferItem** `0x8303` (min 21): `transfer_id: u32`, `item_index: u32`, `item_kind: u8`
(1 file, 2 directory, 3 clipboard format), `format: u16` (clipboard: 1 text UTF-8, 2 HTML UTF-8,
3 PNG, 4 RTF; files: 0), `size: u64`, `path: str ≤ 1024`.
Paths are relative, `/`-separated, NFC-normalised. Absolute paths, empty segments, `.` and `..`,
and names reserved on Windows are rejected by the receiver (`TransferCancel`).

**TransferChunk** `0x8304` (min 20): `transfer_id: u32`, `item_index: u32`, `offset: u64`,
`data: blob ≤ 262 144`. Offsets are contiguous per item.

**TransferItemEnd** `0x8305` (min 40): `transfer_id: u32`, `item_index: u32`, `sha256: bytes32`.

**TransferEnd** `0x8306` (min 4): `transfer_id: u32`.

**TransferCancel** `0x8307` (min 6): `transfer_id: u32`, `reason: u16` (1 user, 2 declined,
3 bad path, 4 disk error, 5 integrity, 6 superseded, 7 too large).

**TransferResume** `0x8308` (min 16): `transfer_id: u32`, `item_index: u32`, `offset: u64`
(receiver already holds bytes `[0, offset)` of that item).

### Topology & config

**ScreenInfo** `0x8401` (min 14): `info_seq: u32`, `cursor_x: i32`, `cursor_y: i32`,
`monitors: list<Monitor>` (1–16).
Monitor = `monitor_id: u32`, `x: i32`, `y: i32`, `width: u32`, `height: u32` (pixels, global
coordinates), `scale_permille: u16` (1000 = 1×), `width_mm: u16`, `height_mm: u16` (0 unknown).
Size 26 bytes.

**ScreenInfoAck** `0x0402` (min 4): `info_seq: u32`. Until acked, the peer ignores
`MouseAbsolute` (spec 01).

**ConfigPush** `0x0403` (min 12): `config_version: u64`, `document: blob` (UTF-8 JSON ≤ 60 KiB;
schema versioned inside the document).

## 9. Trust and pairing

- Each machine has a long-term **Ed25519** key and a self-signed certificate. Peers are pinned by
  **SHA-256 of the SubjectPublicKeyInfo** together with their `machine_id`.
- TLS 1.3 only, both sides present certificates. For pinned peers, verification = SPKI hash
  match. Anything else fails the handshake.
- **Pairing** (unknown peer): the TLS handshake is accepted without pinning, `Hello` is
  exchanged, then either side sends `PairStart`. Both sides compute a **short authentication
  string**:
  `SAS = TLS-Exporter(label "EXPORTER-PortalSwitch-pairing", context = SPKI_hash_low || SPKI_hash_high, 8 bytes)`
  where the two SPKI hashes are ordered bytewise. The code shown is `u64_le(SAS) mod 10^6`
  as six digits. The user confirms the codes match on **both** machines; each side sends
  `PairConfirm(accepted)`. Both accepted → pin and continue the session. Otherwise
  `Goodbye(PAIRING_REJECTED)`.
- A man-in-the-middle terminates two different TLS sessions, so the codes differ (success chance
  10⁻⁶ per attempt). Attempts are rate-limited: 3 failures per remote address → 60 s lockout.
- Until pairing completes, only session and pairing messages are accepted.

## 10. Transport mappings (provisional)

Both mappings provide the link abstraction of §3 and carry identical frames.

### A — Two TCP + TLS connections
- Control connection: ALPN `portalswitch/1`, `TCP_NODELAY`, small send buffer.
- Bulk connection: ALPN `portalswitch/1-bulk`, opened by the initiator after `SessionStart`,
  first frame `BulkAttach`. Both connections present the same client certificate.
- Liveness covers both connections; either dying kills the link.

### B — QUIC (single connection)
- ALPN `portalswitch/1`. Control = first client-initiated bidirectional stream; bulk = one
  additional bidirectional stream (or one stream per transfer). Control stream has the highest
  send priority. No unreliable datagrams in v1.
- `BulkAttach` is not used (streams are already bound to the authenticated connection).

Choice criterion (ADR-0003): input latency (p95/p99/max) while bulk traffic saturates the link,
under loss, on wired and Wi-Fi networks. Decided after the two-machine measurements.

## 11. Sending rules and backpressure

- Control frames are written immediately (no batching beyond what the transport does).
- The control sender keeps a **bounded queue**. When the transport is not writable: consecutive
  `MouseMotion` frames are merged; `Key`, `MouseButton`, `Wheel`, `Enter`, `Leave` are never
  dropped or reordered. If the queue stays full for 1 s → link considered stalled → dead.
- Bulk senders rely on transport flow control; receivers stop reading when their sink (disk,
  clipboard) is slow. Bulk can never delay control because they never share a send queue.
- Clipboard and files are only ever sent on bulk.

## 13. Open points

- Transport choice (A vs B): pending real-network measurements.
- Whether to send `MouseMotion` as relative only, or include sub-pixel fractions for
  high-resolution trackpads (measured trackpad deltas are integers; revisit with external mice).
- Compression for bulk (zstd per transfer, negotiated as a capability).
